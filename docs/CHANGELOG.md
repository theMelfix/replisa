- 2026-06-09 · 2.2.1-2.2.6 · — · Webhook Meta (E2.2 completo). `GET /webhook` verifica challenge (`hash_equals` sul verify token); `POST /webhook` riceve eventi. ## Sprint 3 — Flussi & Dashboard (Settimane 5-6)

- 2026-06-09 · 3.1.2-3.1.5 · — · Welcome Flow (E3.1, lato codice). Nuovo `App\Services\Automation\WelcomeFlow` (scoped per-tenant come `WhatsAppService`), agganciato a `ProcessWhatsAppWebhook`. Trigger primo contatto su `$contact->wasRecentlyCreated`, eseguito solo sui messaggi appena loggati (no doppio invio su webhook riconsegnato). `greet()` invia il menu interattivo via `sendButtons` (free-form nella finestra 24h → nessun template Meta richiesto); testo, header/footer e bottoni personalizzabili per-tenant via `automations.config`, con default Info Servizi/Prenota/Parla con noi. - 2026-06-10 · 3.2.2-3.2.4 · — · Reminder Appuntamento (E3.2, lato codice). Nuovo `App\Services\Automation\AppointmentReminder` (scoped per-tenant) + command `replisa:send-reminders` schedulato `->hourly()->withoutOverlapping()` in `routes/console.php`. `dispatchDue()` trova gli appuntamenti `scheduled` con un reminder dovuto e li invia: due finestre (-24h / -2h, configurabili via `automations.config.offsets`) gestite in modo idempotente sull'unica colonna `reminded_at` calcolando l'offset "dovuto" più urgente non ancora coperto. `remind()` invia il **template** `appointment_reminder` (obbligatorio fuori finestra 24h) con body params nome/data/ora; i fallimenti API sono loggati senza marcare `reminded_at` (retry al giro dopo). Coperto da 10 test Pest. ⚠️ Prod: serve cron `schedule:run` (deploy/README aggiornato) e il template Meta 3.2.1 approvato. 3.2.5 (endpoint API appuntamenti) differito a E4.3 (dipende da Sanctum)
